# Checkpoint: что показываем КРОК

## Тезис за 20 секунд

Токены и вызовы инструментов показывают стоимость агента, но не его пользу.
Prompt Radar связывает каждый запрос с бизнес-сценарием и считает три величины:
потенциальную ценность, подтверждённую ценность и разрыв между ними. Поэтому
CTO видит не «агент сделал 20 tool calls», а «один успешный результат стоит
столько-то, возвращает столько-то и вот где теряются деньги».

## Что уже реализовано

- типизированный формат OpenAI-compatible request;
- формат событий с пользователями, департаментами, usage и tool traces;
- отдельная gold-разметка, недоступная анализатору;
- редактируемые финансовые допущения;
- OpenAI-compatible клиент без привязки к конкретной модели;
- воспроизводимый синтетический корпус из 188 уникальных запросов;
- методика Potential Value → Realized Value → Value Gap;
- тесты контрактов и провайдера.

## Демонстрация

1. Показать исходный payload: настоящий вопрос спрятан в большом RAG-контексте.
2. Показать извлечённый вопрос и Intent Capsule.
3. Показать категорию и найденный сценарий.
4. Показать operational log за 60 дней.
5. Показать итог:
   - Potential Value;
   - Realized Value;
   - TCO;
   - ROI low/base/high;
   - Value Gap;
   - стоимость успешного результата.
6. Открыть сценарий с самым большим Value Gap и объяснить решение для CTO.

## Почему датасет устроен в два слоя

`188` запросов — это эталонный корпус разнообразных намерений для проверки
классификации. Раздувание его тысячами почти одинаковых перефразов завысило бы
качество.

Отдельный генератор создаёт `1500+` событий использования: даты, пользователи,
агенты, токены, tool calls, результаты, повторы и feedback. Этот слой нужен для
MAU, трендов и экономики.

## Если спросят «почему можно верить ROI?»

Мы не выдаём синтетический ROI за боевой. Всё измеряемое берём из логов, а
неизмеряемое показываем как редактируемое допущение с low/base/high. На боевых
данных формулы и сервис остаются теми же; КРОК калибрует ручное время и стоимость
инфраструктуры.

## Если спросят «зачем локальная модель?»

Локальная OpenAI-compatible модель является следующим этапом, а не частью
текущего checkpoint. Целевая версия должна передавать ей только короткий intent
для UNKNOWN и низкоуверенных случаев. Очевидные запросы остаются на дешёвом
baseline.
